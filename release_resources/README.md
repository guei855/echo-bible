# Echo Bible release resources

These files are generated by `dart run tool/prepare_release_resources.dart` and
are deliberately excluded from Flutter assets. Publish the directory contents
as GitHub Release assets while preserving the relative paths in
`resources_manifest.json`.

Build the app with:

```text
--dart-define=ECHO_BIBLE_RESOURCE_BASE_URL=https://github.com/OWNER/REPO/releases/download/resources-v1
```

The release endpoint must expose the relative paths from the manifest (or an
equivalent HTTPS CDN layout). Never publish a resource before its source,
licence, byte size and SHA-256 in the manifest have been reviewed.

Installation is atomic: Echo Bible downloads to `.part`, checks exact size,
SHA-256 and `PRAGMA integrity_check`, then renames the file into application
storage. A failed temporary file is deleted.
# Ressources bibliques — GitHub Releases

Les modules présents dans `fr/bibles/` sont prêts à être hébergés, mais ne sont
pas encore publiés. Ne renseigner aucune URL fictive dans le manifeste.

1. Créer une release GitHub nommée `v1.0.0-resources`.
2. Téléverser `darby.db`, `ostervald.db` et `neo_crampon.db` depuis
   `release_resources/fr/bibles/`.
3. Copier les trois URL HTTPS définitives des assets.
4. Ajouter chaque URL sous la clé `downloadUrl` correspondante dans
   `resources_manifest.json`, puis passer son `status` à `available`.
5. Compiler l’application avec
   `--dart-define=ECHO_BIBLE_RESOURCE_BASE_URL=<URL_DE_BASE>` si les assets
   suivent la structure `<base>/fr/bibles/<fichier>.db`.

Les tailles et SHA-256 du manifeste doivent être recalculés si un fichier est
reconstruit, même si son numéro de version ne change pas.
